# סרטון "למה בנינו את הדף השבועי"

סרטון קידום אנכי של 43 שניות, שמסביר לצוותים ולהורים מה זה הדף השבועי.
**אינו חלק מהאפליקציה** ואינו מקושר ממנה. כל הקוד שלו יושב בתיקייה הזו.

| | |
|---|---|
| גרסה מלאה | `hadaf-promo.mp4` — 1080×1920, ‏60fps, ‏H.264 + AAC, ‏~20MB |
| גרסת וואטסאפ | `hadaf-promo-whatsapp.mp4` — 720×1280, ‏30fps, ‏~7.8MB |
| אורך | 43.0 שניות בדיוק (2580 פריימים) — כאורך קובץ המוזיקה |

שני ה-mp4 **אינם בריפו** (ראו "חומרים שאינם בריפו" למטה).

---

## איך זה בנוי

* `promo.html` — הסרטון עצמו. דף אחד שמצייר כל פריים מתוך הזמן `t` בלבד,
  בלי טיימרים ובלי CSS transitions. לכן כל פריים זהה בכל הרצה.
  פתיחה בדפדפן: מנגן בלולאה. `?t=19.25` — קופא על שנייה מסוימת.
* `render.js` — מקליט: פותח את הדף ב-Chromium (Playwright), קורא
  ל-`seekAsync(t)` לכל פריים, מצלם ושולח ל-ffmpeg. בסוף מצמיד את
  `music.m4a` אם קיים.
* `check.js` — הבדיקות האוטומטיות על הסרטון המוכן (פירוט למטה).
* `heebo-*.woff2` — הגופן Heebo, יושב כאן ולא מגיע מ-CDN.
* `img/` — התמונות. הלוגו נטען מ-`../../logo.js` (`LOGO_MARK`).

### הבמה

הבמה בנויה ביחידות של **478×850** (המידות מהבריף המקורי) ומצולמת בצפיפות
פיקסלים 1080/478 = 2.26. כך הטקסט והתמונות מצוירים בחדות מלאה של 1080×1920,
ולא מוגדלים מפריים קטן. כל המידות בקוד הן ביחידות של 478.

### פרטים בכל חלק שכדאי לדעת

* **מסך המספרים (3).** הצילום הוא מהאפליקציה; המספרים מצוירים מעליו:
  * `STATS` בראש החלק: `top` — המספר הגדול [לפני, אחרי], כרגע 321→322.
    **זה המקום לעדכן כשהמספרים עולים.**
  * `all`/`done` — השורה התחתונה ("87→99 מתוך 237→238 סיימו את דף ב.").
    הוחלט **לא** לעדכן אותה למספרים של היום: בתחילת שבוע מעטים סיימו,
    וזה לא ייצוגי.
  * אחרי שנייה וחצי (`STATS.at`), בקפיצה אחת (לא גלגלת, לא "+1"):
    המספר הגדול +1, "אבות ובנים" 102→103, ו"סיימו" עולה עם הרצועה.
  * המילים העבריות בשורה התחתונה נלקחות מהצילום (`LINE`), ורק
    הספרות מצוירות. כל המיקומים נמדדו בפיקסלים של `3-stats.jpg`; צילום
    חדש = מדידה חדשה (`ink`, `box`, `strip`, `LINE`, גבולות הרצועה ב-`statBar`).
* **האיורים (5).** מצוירים על canvas אחד. סדר הנחיתה: טבלה, סוכות, מים —
  כל כרטיס מעל הקודם.
* **הסימון (6).** שתי השורות הצהובות נמשכות מימין לשמאל; מיקומן נמדד
  בפיקסלים של `6-mark.jpg` (`hls`).
* **וואטסאפ (10).** `MSG` הוא נוסח ההודעה. ההקלדה בקצב קבוע של ~32 תווים
  לשנייה, ו"נשלח" (וי כחול, "מחובר") חצי שנייה אחרי סוף ההקלדה —
  הודעה ארוכה יותר פשוט מסתיימת מאוחר יותר. בהודעה ארוכה מאוד לבדוק
  שנשאר זמן לפני "תודה".
* **תודה (11).** מסך הוואטסאפ נשאר עמום מאחוריה (`outMax`) ואז נעלם
  לגמרי (`outRest`), כך שהסוף נקי.

## הפקה

```bash
NM=$(dirname $(readlink -f $(npm root -g)/playwright))
NODE_PATH=$NM node tools/promo/render.js      # ~20 דקות, 2580 פריימים
node tools/promo/check.js                     # הבדיקות
```

### הקלטת קטע בלבד (שינוי קטן — דקה במקום עשרים)

`FROM`/`TO` הם מספרי פריימים (שנייה × 60). הקטע יוצא בלי שמע
ל-`video-only.mp4`, ומשתילים אותו בסרטון שקט קיים:

```bash
FROM=480 TO=720 NODE_PATH=$NM node tools/promo/render.js
ffmpeg -i silent.mp4 -i video-only.mp4 -filter_complex \
 "[0:v]trim=end_frame=480,setpts=PTS-STARTPTS[a];[1:v]setpts=PTS-STARTPTS[b];\
  [0:v]trim=start_frame=720,setpts=PTS-STARTPTS[c];[a][b][c]concat=n=3:v=1[v]" \
 -map "[v]" -c:v libx264 -preset slow -crf 15 -pix_fmt yuv420p -r 60 silent-new.mp4
```

לשמור תמיד עותק **שקט** של הסרטון המלא — עליו משתילים, ואליו מצמידים מוזיקה.

### מוזיקה, וגרסת הוואטסאפ

```bash
F="atrim=0:43,volume=6dB,afade=t=in:d=0.25,afade=t=out:st=41:d=2,aformat=sample_rates=48000:channel_layouts=stereo"
# מלאה
ffmpeg -i silent.mp4 -i tools/promo/music.m4a -filter_complex "[1:a]$F[a]" \
  -map 0:v -map "[a]" -c:v copy -c:a aac -b:a 192k -t 43 -movflags +faststart hadaf-promo.mp4
# וואטסאפ
ffmpeg -i silent.mp4 -i tools/promo/music.m4a -filter_complex \
  "[0:v]fps=30,scale=720:1280:flags=lanczos[v];[1:a]$F[a]" -map "[v]" -map "[a]" \
  -c:v libx264 -preset slow -crf 19 -maxrate 2500k -bufsize 5000k -profile:v main -level 3.1 \
  -pix_fmt yuv420p -g 60 -c:a aac -b:a 128k -t 43 -movflags +faststart hadaf-promo-whatsapp.mp4
```

הקובץ המקורי שקט יחסית (שיא ‎-9.3dB) — ההגברה של 6dB מביאה לשיא ‎-3.3dB, בלי עיוות.

### הבדיקות (`check.js`)

1. **קפיצות** — הפרש בין פריימים עוקבים שחורג מהשכנים. צריך: "אין".
2. **שכפול פריימים** בקטעי הזום. ✗ בקטע האחרון (38.4–42.9) **צפוי ואינו
   תקלה**: מסך הוואטסאפ דועך שם מ-15% לאפס, ולווידאו של 8 ביט יש רק ~38
   דרגות בטווח הזה — חלק מהפריימים זהים. בעין זה לא נראה.
3. **הכותרת** — אזור הלוגו זהה בכל הפריימים.
4. **אורכים** — וידאו ושמע 43.0.

את מספר הפריימים הצפוי (2580) ואת טווחי הזום יש לעדכן ב-`check.js` כשמשנים את האורך.

## לקחים — מה נשבר בדרך ואיך תוקן

* **זום עם CSS transform קופץ.** Chromium מרסטר מחדש תמונות מוגדלות
  בקפיצות של גודל (כל ~0.75 ש׳), גם עם `will-change`. לכן כל כרטיס עם זום
  מצויר על **canvas** בכל פריים (`drawRect`), בדיוק תת-פיקסלי.
* **טקסט שמוגדל ב-`fillText` קופץ** בין גדלים קבועים. "תודה!!" מצויר פעם
  אחת בחדות גבוהה ומוקטן כתמונה.
* **מעבר בין חלקים** — כולם דרך `xfade` אחת (smoothstep), והיוצא הוא בדיוק
  1 פחות הנכנס. השכבות מחוברות ב-`mix-blend-mode: plus-lighter`, כך
  שבאמצע המעבר אין צלילה לרקע. **חריג:** "תודה!!" היא שכבה רגילה מעל —
  בחיבור הזהב התבהר על רקע הצ'אט.
* **הכותרת והרקע** מצוירים פעם אחת ואינם זזים. בגרסה ישנה הכותרת קפצה
  12 פיקסלים באמצע — לא לשים אותם בתוך חלק.
* **וואטסאפ דוחס** כל סרטון שנשלח כמדיה: מוריד לרבע רזולוציה ולחצי
  פריימים. לכן גרסת וואטסאפ נפרדת, מתחת ל-16MB, עם ערוץ שמע (בלי שמע
  וואטסאפ מציג לפעמים כ-GIF). לשלוח עם HD, או כ"מסמך" לאיכות המלאה.
* **מסביבת הפיתוח חסומים** YouTube (אי אפשר להוריד מוזיקה מקישור — צריך
  קובץ) ו-docs.google.com (אין גישה למספרים החיים — צריך צילום או מספרים).
* **פונט:** Heebo המשתנה (100–900) בקובץ אחד; הספרות שלו מבוססות Roboto,
  ולכן ספרות שמצוירות מעל צילום מהאפליקציה משתלבות.
