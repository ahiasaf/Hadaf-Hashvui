# הדף השבועי — מסמך מסירה למתכנת

מסמך למי שנכנס לקוד. מניח ידע בג׳אווהסקריפט ולא מניח שום היכרות
עם הפרויקט. הערות הקוד עצמן מפורטות ובעברית — הן מסבירות **למה**,
לא **מה**, ולרוב הן התיעוד האמיתי.

---

## מה זה

תוכנית לימוד של רשת ישיבות בני עקיבא: **דף גמרא אחד בשבוע, מסכת
בשנה**, לתלמידים שהגמרא קשה להם. שתי מסכתות פעילות — תענית ומגילה.

יש כאן שלוש אפליקציות שחולקות קבצי נתונים:

| קובץ | מה זה | קהל |
|---|---|---|
| `index.html` | האפליקציה — לוח שנה, חומרי הדף, הרשמה, וגם `/admin` | תלמידים, ראשי חטיבות, רכז |
| `studio.html` | חלוקת הדף לקטעים וקישורם לביאור | הרכז ועוזרי עריכה |
| `learn.html` | הלימוד עצמו — חלון נע על צורת הדף | תלמידים |
| `lab.html` | מעבדה לניסוי שיטת זיהוי חדשה | פיתוח בלבד |

---

## אילוצי הבנייה — לקרוא לפני שנוגעים

* **אין שלב בנייה.** אין npm, אין באנדלר, אין טרנספילציה. קובץ HTML
  אחד לכל אפליקציה, עם ה-CSS וה-JS בתוכו. `git push` הוא הפריסה
  (Vercel).
* **ES5 בלבד.** בלי `let`, בלי חיצים, בלי `class`. לא מתוך שמרנות
  אלא מפני שהמכשירים בשטח הם טלפונים ישנים של תלמידים.
* **בלי רשת חיצונית בזמן ריצה.** pdf.js מצורף ב-`vendor/`. אין CDN.
* **PWA.** `sw.js` מחזיק `CACHE_NAME` שחייב להתעדכן יחד עם
  `APP_VERSION` שב-`index.html`, אחרת מכשירים נתקעים על גרסה
  מעורבת — index חדש עם data ישן — וזה שובר מסכים שלמים.

## הנתונים

```
data.js     לוח השנה, המוסדות, המחירים, וכל המלל הניתן לעריכה
links.js    DAF_LINKS[מסכת][דף] = [קישור צורת הדף, קישור חברותא]
logo.js     הלוגו כ-data URI
```

**אין מסד נתונים.** גיליון גוגל הוא האחסון:

* **קריאה** — `gviz/tq?tqx=out:csv` ישירות מהדפדפן. הגיליון הציבורי
  משותף כ"כל מי שיש לו הקישור — מציג".
* **כתיבה, וקריאת לשוניות פרטיות** — `apps-script.gs`, שרץ בחשבון
  של הרכז. הוא טיפש בכוונה: מקבל `{action:'table', tab, cols, rows}`
  וכותב. הוא אינו יודע דבר על התוכן, ולכן עמודה חדשה או לשונית
  חדשה אינן דורשות פריסה מחדש.
* קבצי הדף עצמם יושבים ב-Google Drive, ונמשכים דרך אותו סקריפט
  (`doGet?file=<id>`). **הסיבה:** דרייב אינו שולח כותרת CORS,
  והדפדפן אינו מרשה לקרוא ממנו פיקסלים. הסקריפט הוא גשר, לא שרת.

לשוניות: `מוסדות`, `הרשמות`, `חידות`, `טקסטים`, `סימוני הדף`,
`אנשי קשר` (פרטית), `יומן שיחות`.

## `studio.html` — הזיהוי והסימון

הלב של הפרויקט. שני שלבים: **כיול** ואז **סימון**.

### כיול — למצוא את הגמרא בתוך דף וילנא

הקלט הוא PDF סרוק. `ink()` הופך אותו למסכת ביטים, ו-`analyse()`
מחפש את הגמרא לפי **מרזבים**: שני הרווחים האנכיים שמפרידים בין
הגמרא לרש"י ולתוספות.

```
analyse(m, w, h)
  ├─ colSum / smooth      פרופיל דיו לכל עמודה
  ├─ מרזבים L,R           ממוצע נע, סף 0.45
  ├─ zones                רצפים שבהם צמד המרזבים אינו משתנה
  ├─ סינון לפי pitch      אזור שמרווח השורות בו כשל פירוש — יורד
  └─ snapZones            הצמדת הגבול לתפר שבין השורות
```

מבנה `S` (הכיול הנוכחי):

```js
S = { w, h, bbox, gpitch, cpitch,
      core:[bx0,bx1],      // המסגרת החיצונית
      spine:[gA,gB],       // המסגרת הפנימית
      zones:[ { y0,y1, a,b, inA,inB, pitch, lines:[[t,b],…] } ] }
```

`inA`/`inB` הם מתגים ולא גרירה חופשית: כל צד של אזור נמצא באחד
משני מצבים בלבד — על המסגרת הפנימית או מורחב אל החיצונית. זו
החלטה מכוונת; היא מדויקת יותר ועובדת באצבע.

**היכן זה נופל, ולמה יש `lab.html`:**

* מילה מרחפת שוברת את המרזב.
* פירוש שנגמר באמצע הדף — הגמרא מתרחבת, ומרווח השורות שלה קרוב
  מספיק לפירוש כדי שהמסנן יזרוק את הגוש.
* המעבר מטור צר לרחב נמצא כחצי שורה מוקדם מדי (`snapZones` מטפל
  בזה, ומודד את השורה שעל הגבול במקום להעריך).

### סימון

קטע נסגר בנקודה `(שורה, x)` ולא בשורה שלמה — `x` הוא שבר מהקצה
**הימני** של השורה, כלומר מתחילת הקריאה.

```js
step = {
  g: { from:{line,x}, to:{line,x} },     // בגמרא
  c: { from, to, text, h },              // פסקאות בחברותא + HTML שמור
  cont: 1                                // המשך של קטע שהתחיל בעמוד הקודם
}
```

הכל נשמר תחת `BOOK[מסכת|דף|מקור|עמוד]`, ומשם ללשונית `סימוני הדף`.

שלוש נקודות שלא מובנות מאליהן:

* **`c.h`** — ה-HTML של הביאור נשמר בזמן הסימון. בזכות זה מסך
  הלימוד אינו צריך לפתוח את ה-PDF של חברותא בכלל.
* **`cont`** — סוגיה חוצה את גבול העמוד וגם את גבול הדף. היא
  נשמרת כשני חלקים עם אותו ביאור, והשני מסומן `cont`.
* **`prev` / `prevDaf`** — נקודת עצירה. השיעור אינו נגמר תמיד בסוף
  הדף; לפעמים הוא גולש כמה שורות אל הדף הבא. הסימון נעשה **בדף
  שאליו גלש** ונשמר שם, ולכן מסך הלימוד מוצא את הזנב בלי לדעת
  דבר על סדר הדפים.

**עמידות:** כל שינוי נכתב ל-localStorage מיד (`touched()`), ורק
לחיצת שמירה כותבת לגיליון. `keepPageState()` בונה את רשומת העמוד
מחדש — ולכן כל שדה שאינו נגזר מהמסך (`splits`, `cal`, `prev`)
חייב להיות מועבר שם במפורש. זה כבר נשבר פעם אחת ומחק פיצולים.

## `learn.html` — מסך התלמיד

חלון נע על צורת הדף. הקטע הנוכחי חד, השאר מעומעם.

* `shapes()` → `bands()` → `outline()` — מלבן לכל שורה, איחוד
  לרצועות רציפות, ואז **מסלול אחד** שמשמש גם כחור במסכה וגם
  כמסגרת. שתי דקויות: `nip` מזיז את שני קצוות הקטע **שמאלה**
  (כך קטעים עוקבים נשארים צמודים ולאות האחרונה יש אוויר),
  ו-`air` מרחיב רק בקצה שהוא גבול הטור ולא בתפר שבין קטעים.
* `focus()` — רוחב החלון הוא **הטור של הקטע**, לא הדף ולא הגוש
  המרכזי. בטלפון זה ההבדל בין קריא ללא קריא.
* `DIM` — כיבוי העמעום בלבד. לא זום, לא שינוי מיקוד.
* צורת הדף מגיעה מ-`daf/<מסכת>/<דף>-a|b.webp` כשהיא קיימת
  (`tools/build-library.py` ממיר פעם אחת), ורק בהיעדרה נופלים
  לדרייב. **זה קריטי:** מסך התלמיד לא יכול להישען על ה-Apps
  Script של הרכז — מכסה, ריצות מקבילות, וחשבון גוגל אחד.

## `lab.html` — הכיוון החדש, ומה מצבו

הזיהוי הנוכחי מחפש **רווח**. המעבדה בודקת מה שהעין עושה בשנייה:
**הגמרא כתובה גדול יותר**.

```
detect()
  ├─ bbox                 הסרת שוליים
  ├─ ~90 רצועות אנכיות    לכל אחת: רצפי דיו וגובהם
  ├─ split2               שני אשכולות על ציר הגובה → סף
  ├─ big                  רצף גדול, נשפט יחד עם שכניו באותו טור
  ├─ solid                2 מתוך 3 רצועות סמוכות מסכימות
  ├─ lines                שורות: רצף שורות פיקסלים עם מספיק רצועות
  └─ zones                שורות מתאחדות לפי חפיפת מוטה + גובה שורה
```

**החלטות שנקנו ביוקר** (כל אחת נבעה מכישלון אמיתי):

1. הסף אינו באמצע בין האשכולות אלא ב-0.62. היחס בדף אמיתי הוא
   ~1.6, לא כפול, ולזנבות של ל/ק/ך יש גובה.
2. רצף נשפט לפי החציון שלו ושל שכניו **בטור** — אות ארוכה ברש"י
   עומדת בין נמוכות, בגמרא כל השורות גבוהות.
3. יחידת ההרכבה היא **שורת טקסט**, לא שורת פיקסלים. אותיות אינן
   מתחילות באותו x בכל שורה.
4. שורת גמרא חייבת רוחב מינימלי, אחרת זוג רצועות דביקות בשוליים
   מחזיק "שורה" פתוחה לאורך כל הדף.
5. המוטה נמדד מ-`big` ולא מ-`solid` — ההרחבה נועדה למצוא שורות,
   ולא לקבוע גבולות.
6. שברירים מסוננים **לפני** האיחוד, אחרת שני חלקי הגמרא לא
   נבדקים זה מול זה כי שבריר יושב ביניהם.

**מצב נוכחי:** מוצא את הגמרא בדפים אמיתיים, רץ ב-20–50ms. רוחב
הטור יוצא ~107% מהאמת, ולפעמים נוצרים אזורים רבים מדי (4–7 במקום
2–3). הכיוון עובד; ההידוק לא הושלם.

**איפה הייתי מחפש הלאה:** אשכול על מוטות השורות במקום איחוד
סדרתי של שכנים; ושילוב עם אות המרזב הקיים כאישוש הדדי במקום
כתחליף.

## מה שכדאי לדעת לפני שנוגעים

* `learn.html` ו-`studio.html` הם 2000+ שורות כל אחד. הערות
  הבלוק מסבירות למה משהו נעשה כך; אם משהו נראה מוזר, יש סיכוי
  טוב שהתשובה כתובה שם.
* **בדיקות:** אין רץ בדיקות בריפו. הן נכתבו כתסריטי Playwright
  לאורך העבודה, ומריצות את הקוד האמיתי מול תמונות מדומות. אם
  ממשיכים — כדאי להכניס אותן פנימה.
* אין TypeScript ואין מודולים. במודע.
* **`/admin` אינו מקושר משום מקום** ואינו במניפסט. אין להוסיף
  קישור אליו.
* **אין טלפונים בריפו.** הריפו ציבורי, ורשימות אנשי הקשר יושבות
  בלשונית פרטית שרק ה-Apps Script קורא.
