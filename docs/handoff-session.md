# הדף השבועי — מסמך מסירה לשיחה חדשה

מסמך אחד להעביר לשיחה חדשה, כדי שלא נתחיל מאפס.
המסמך הטכני המלא הוא `docs/HANDOVER.md`; זה משלים אותו, ומתמקד
במה שסוכם בשיחות ובמה שנלמד מהן.

---

## 1 · עם מי עובדים, ואיך

**אחיאסף פנש** — מרכז את "הדף השבועי" ברשת ישיבות בני עקיבא.
**לא לכתוב "הרב".**

היעד שהוצב לו: **2000 תלמידים** השנה. אשתקד היו 350.

### הוראות עבודה קבועות — לכבד אותן, הן נאמרו יותר מפעם אחת

* **לדחוף ישירות ל-`main`.** לא ענף, לא PR.
  *"אני לא צריך שתעשה תיקונים בענף נפרד תעשה אותם ישר בmain"*
* **לדבר על אפקט למשתמש, לא על קוד.**
  *"תפתח קודם כל בפרקטיקה באפקט על המשתמש"*
* **לנתח לפני שמתכנתים.** לרוב הוא רוצה לראות תוכנית ולהגיב עליה.
* **בלי גרסאות שבורות.** הוא כבר מפיץ את האפליקציה לצוות.
  *"אל תעשה לי גרסה עכשיו עוד פעם עם באגים כאלה"*
* **לא להגזים בהגנות.** "האם אתה בטוח" מספיק; הקלדת שם לאישור
  היא הגזמה. הוא אמר את זה במפורש.
* **הוא אוהב אוטומציות** ורוצה מוצר שלם שאפשר לשכפל לתוכניות
  נוספות. כל פעולה ידנית חוזרת היא חוב.

### כמה החלטות עיצוב שהוא קבע, ואין לחזור עליהן

* **משוב, לא פרסים.** מוטיבציה מהלימוד עצמו.
* **בלי "ילדותי".** *"אל תתן לו להרגיש ילד קטן"* — ולכן ההזמנה
  בין אב לבן היא **הדדית**, לא "ספר לאבא".
* **בלי הבטחות כתובות.** *"הויזואליה צריכה לדבר את עצמה."*
* **בלי לוח שמראה לתלמיד את כל מה שלא הספיק** — זה מעמיס.
* **הלימוד מתחיל בפרשת בראשית**, ותאריכים עבריים ולא לועזיים.
* התוכנית לכיתות **ז׳–ח׳**; אחרים מצטרפים ונספרים, אבל לא כשכבות.

## 2 · מצב היום

* **גרסת אפליקציה: 7.32.0** · **SCRIPT_VERSION: 14**
* הכל ב-`main`, נפרס אוטומטית ל-Vercel. אין שינויים לא־מחויבים.
* אישור וגשל לשימוש בדפי הגמרא **התקבל**; הם ביקשו קישור לרכישה,
  והוא קיים בשער הכניסה של מסך הלימוד.

### מה שנבנה בשיחה האחרונה

| | |
|---|---|
| **פרסום שמאמת** | "פרסום" קורא חזרה מהגיליון ומשווה. רק מה שחזר נחשב מפורסם. |
| **בדיקת "מה רואה מי שנכנס עכשיו"** | קוראת מהגיליון בלי הטיוטה המקומית ומדווחת שורה־שורה. |
| **לשונית "נתונים"** | שני הגיליונות, לשונית־לשונית: מספר שורות, הורדה כ-CSV, ניקוי. |
| **מסך משתתפים** | חיפוש, שבבי סינון לפי ישיבה ולפי דרך לימוד, קיבוץ, ומחיקת שורה. |
| **שני קישורים בלוח** | כחול לצוות, ירוק לתלמידים, עם אזהרה שלא להחליף. |
| **מאפייני פרויקט** | `PRIVATE_ID` ו-`READ_KEY` יושבים ב-Script Properties. |
| **קישורים אישיים** | קוד לכל מוסד, לוח שמי, "קוד חדש", והודעה לקבוצה. |

### הקישורים האישיים — איך זה עובד

```
join.html?inst=avir            פתוח · לתלמידים ולהורים
board.html?inst=avir&k=7fq2    הלוח לצוות · הקוד הוא ההרשאה
```

* הקוד נוצר **בצד הלקוח** ברגע ההרשמה ונשלח עם `action:'register'`
  — כי `no-cors` אינו מחזיר תשובה, ומי שמייצר הוא היחיד שיודע.
  השרת שומר רק אם אין קוד (`ensureCode_`), כדי שקישור שכבר הופץ
  לא יישבר.
* `board.html` שומר את הקוד במכשיר בפתיחה הראשונה **ומנקה אותו
  מהכתובת** (`history.replaceState`) — הלוח הוא מסך שמצלמים.
* קוד שגוי אינו נשמר, אחרת היה נדבק למכשיר וחוסם את הקישור הנכון.
* מהשרת יוצאים **שמות פרטיים בלבד** — בלי משפחה ובלי טלפון.
* הקוד שייך **למוסד ולא לאדם**: כמה אנשי צוות מעבירים את הקישור
  ביניהם בלי הרשמה שנייה.
* הקודים יושבים בלשונית פרטית `קודים`. בניהול ← מוסדות יש
  "משיכת הקודים מהגיליון" ו-↻ לקוד חדש לכל מוסד.
* **"הודעה לקבוצה"** נושאת תמיד את קישור התלמידים ולעולם לא את
  קישור הלוח.

## 3 · הארכיטקטורה בעמוד אחד

PWA סטטית. **ES5 בלבד**, בלי שלב בנייה, בלי CDN. `git push` = פריסה.

**ארבע גרסאות חייבות להיות זהות**, ו-`tools/preflight.py` אוכף:
`APP_VERSION` (index.html) · `CACHE_NAME` (sw.js) ·
`STUDIO_VER` (studio.html) · `DAF_REV` (data.js)

`preflight.py` בודק גם **שמות משתנים כפולים** ו**מחלקות CSS יתומות**.
שתי הבדיקות נוספו אחרי תקלות אמיתיות. להריץ לפני כל דחיפה.

### אחסון — גיליון גוגל, בלי מסד נתונים

* **קריאה ציבורית:** `gviz/tq?tqx=out:csv` ישירות מהדפדפן.
* **כתיבה:** `apps-script.gs`, `doPost` עם `mode:'no-cors'`.
* **מחיקה וקריאה פרטית:** דרך `doGet` (תשובה שאפשר לקרוא), עם `READ_KEY`.

**מזהה הגיליון הציבורי יושב ב-`data.js`** — כלומר כל מה שנכתב אליו
גלוי לכל מי שפותח את קוד המקור. לכן:

```
PRIVATE_TABS = ['לומדים','לימוד','הרשמות','חידות']   → גיליון סגור
לשוניות ציבוריות: מונים, מוני-לימוד, מוסדות, הגדרות, טקסטים, סימוני הדף
```

### שלוש שכבות הגדרות

`CV(k)` = מפורסם (`PUB_CFG`, מלשונית `הגדרות`) + טיוטה מקומית (`CFG`) מעליו.
`PUB_KEYS = ['rows','joined','roster','sugya','prices','coordWa','raffle','orderBy','joinLink','weekRaffle']`

## 4 · מלכודות שנקנו ביוקר — לא לחזור עליהן

1. **`no-cors` תמיד "מצליח".** התשובה אטומה. כל כתיבה חייבת קריאה
   חוזרת שמאמתת. הפאנל הכריז "פורסם" חודש שלם על כתיבה שלא נקראה.

2. **גוגל שיטס משנה ערכים.** תא שכתוב בו `true` הופך לבוליאני
   וחוזר כ-`TRUE`. **ו-gviz מנחשת טיפוס אחיד לכל עמודה** — מה
   שלא מתאים חוזר **ריק**. הפתרון: לכתוב עם גרש מוביל (טקסט
   מפורש) ולקרוא בסלחנות (`cfgVal`).

3. **`try { JSON.parse } catch {}` ריק הוא באג.** הוא הפך ארבע
   הגדרות שבורות לשקט מוחלט. כשלון חייב להשאיר סימן.

4. **gviz אינה מודיעה על לשונית חסרה** — היא מגישה את **הראשונה**
   בגיליון. כל קורא חייב לוודא שמה שחזר נראה כמו מה שביקש.

5. **מחיקת CSS לפי טווח בין עוגנים.** מחיקה כזו בלעה שבעה כללים
   ושברה את מסך ההרשמה בייצור. לערוך תוספתית. `check_orphan_classes`
   נועדה לתפוס בדיוק את זה.

6. **כרום זורק שם קובץ שאינו ASCII** ב-`<a download>` ושומר
   "download" בלי סיומת.

7. **הדבקת קוד לסקריפט מוחקת את מה שמולא בו.** נפתר עם Script
   Properties — אבל אם מישהו מחזיר ערכים לקוד, המלכודת חוזרת.

8. **`ss` מפורש בקריאה חייב סיסמה** גם ללשונית שאינה ברשימה
   הפרטית, אחרת אפשר לעקוף את השמירה בשם לשונית "רגיל".

## 5 · מה פתוח

### אצל אחיאסף

* [ ] לפרוס Apps Script **גרסה 14** (Deploy ← Manage deployments ←
      עריכה ← **New version**, לא "New deployment").
* [ ] להגדיר Script Properties: `PRIVATE_ID`, `READ_KEY`
      (גלגל שיניים ← Project Settings ← Script Properties).
* [ ] לבחור לוגו וגשל: ניהול ← טקסטים ← שער הדף (הממיר בנוי).
* [ ] לסמן בסטודיו את דף ב׳ של תענית ומגילה — בלי זה שורת
      "דף אינטראקטיבי" לא מופיעה גם כשהמתג דלוק.

### לפיתוח — מה שנשאר

* **שורה נעה** עם מספרי ישיבות אחרות ומספר הלומדים הארצי.
* **תובנות לימוד** — רק באישור אחיאסף לכל נוסח.

### מוקפא לבקשתו

* **ההגרלות** — *"חכה עם זה"*. `raffle` ו-`weekRaffle` כבויים עד
  שהפרס יאושר; `join.rfPrize` ו-`join.rfImg` ריקים.

## 6 · איך בודקים

אין רץ בדיקות בריפו. הבדיקות נכתבות כתסריטי Playwright בתיקיית
ה-scratchpad ומריצות את הקוד האמיתי מול גיליון מדומה
(`ctx.route('**/gviz/**')` ו-`'**/exec*'`).

```
python3 tools/preflight.py          # גרסאות, כפילויות, מחלקות יתומות
bash scratchpad/srv.sh              # שרת על 8899 משורש הריפו
node scratchpad/smoke.js            # כל המסכים, שתי רזולוציות, בלי שגיאות
```

כרומיום ב-`/opt/pw-browsers/chromium`.
**`docs.google.com` חסום מסביבת הפיתוח** — אי אפשר לקרוא את
הגיליון האמיתי משם, ולכן כל בדיקה עוברת דרך `route`.
